# GitHub Repository Code Explainer

A college mini project that takes a **public GitHub repository URL**, clones it locally, reads source files as text, and asks a **local Ollama LLM** (Qwen) to explain the project in simple language.

The explanation is generated dynamically. It is **not** hard-coded, and **no cloud LLM APIs** (OpenAI, Gemini, Claude) are used.

## Features

- Streamlit form for a GitHub URL
- FastAPI `POST /explain` backend
- GitPython clone into `temp_repos/` (cleaned up after each request)
- Source-file filtering and context size limits
- Local inference with Ollama (`qwen2.5:3b` by default)
- Structured student-friendly explanation (overview, stack, features, flow, files, architecture)
- Clear error messages (bad URL, private/missing repo, Ollama down, missing model, backend down)

## Architecture

```
GitHub Repository URL
        ↓
Streamlit frontend (frontend/app.py)
        ↓  HTTP POST /explain
FastAPI backend (backend/main.py)
        ↓
GitPython clone (read-only; never executed)
        ↓
File filtering + context limits (backend/github_processor.py)
        ↓
Local LLM via Ollama HTTP API (backend/llm_service.py)
        ↓
Explanation JSON
        ↓
Streamlit markdown display
```

## Technology stack

- Python 3.10+
- FastAPI, Pydantic, Uvicorn
- GitPython
- Streamlit
- Ollama + Qwen (`qwen2.5:3b`)
- `requests` for HTTP

## Requirements

- Python 3.10 or newer
- Git installed and available on your PATH (on macOS, install Xcode Command Line Tools: `xcode-select --install`)
- Ollama installed
- A public GitHub repository URL (private repos cannot be cloned without credentials; this project does not log in)

## Installation

From the project root (`github-code-explainer/`):

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

On Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Optional: copy `.env.example` and export the variables, or set them in your shell.

```bash
cp .env.example .env
```

Default settings:

- `OLLAMA_BASE_URL=http://localhost:11434`
- `OLLAMA_MODEL=qwen2.5:3b`
- `BACKEND_URL=http://localhost:8000`

## Ollama installation

**macOS (Homebrew):**

```bash
brew install ollama
```

Or download from: https://ollama.com/download

**Linux:**

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

**Windows:** install the app from https://ollama.com/download

Start the Ollama server (keep this terminal open if needed):

```bash
ollama serve
```

On many desktop installs, Ollama starts automatically in the background.

## Model installation

This project defaults to a small Qwen model that can run on a typical student laptop:

```bash
ollama pull qwen2.5:3b
```

If `qwen2.5:3b` is unavailable on your machine, try:

```bash
ollama pull qwen2.5:1.5b
```

Then set:

```bash
export OLLAMA_MODEL=qwen2.5:1.5b
```

Confirm:

```bash
ollama list
```

## How to start the backend

From the project root, with the virtual environment activated:

```bash
uvicorn backend.main:app --reload
```

The API listens on http://localhost:8000  
Docs: http://localhost:8000/docs

## How to start the frontend

In a **second** terminal, from the project root:

```bash
source .venv/bin/activate
streamlit run frontend/app.py
```

Open the URL Streamlit prints (usually http://localhost:8501).

## How to test

1. Start Ollama, pull the model, start FastAPI, start Streamlit (commands above).
2. Paste a public repo URL and click **Explain Repository**.
3. You should see markdown sections generated by Qwen.

Quick API check (with backend running):

```bash
curl -X POST http://localhost:8000/explain \
  -H "Content-Type: application/json" \
  -d '{"repo_url":"https://github.com/pallets/flask"}'
```

URL validation (no Ollama needed):

```bash
python -m pytest tests/test_github_url.py -q
```

(Install pytest only if you want local tests: `pip install pytest`.)

## Common errors

| Message | What to do |
| --- | --- |
| Please enter a GitHub repository URL | The input was empty. |
| Invalid GitHub URL | Use `https://github.com/owner/repo` (not a file or issues URL). |
| Repository not found / may be private | Confirm the repo is public. |
| Git is not working / Git clone failed | Install Git. On Apple Silicon Macs, install matching Command Line Tools so `git version` works (not an x86_64 vs arm64 mismatch). |
| No supported source files | The repo has no listed source/manifest files. |
| Repository is too large | Try a smaller repo. |
| Ollama is not running | Run `ollama serve`. |
| Model is not installed | Run `ollama pull qwen2.5:3b`. |
| Model took too long | Smaller repo or `qwen2.5:1.5b`. |
| Backend unavailable | Start FastAPI with `uvicorn backend.main:app --reload`. |

## Project explanation

This mini project shows a full local GenAI pipeline:

1. The student pastes a GitHub URL in Streamlit.
2. Streamlit sends JSON `{ "repo_url": "..." }` to FastAPI.
3. FastAPI validates the URL, clones with GitPython into `temp_repos/`, and **only reads** text files (it never runs repository code).
4. A bounded snapshot (README first, then manifests, then `src/` / main files) is sent to Ollama.
5. Qwen writes a structured explanation. FastAPI returns `{ "explanation": "..." }`.
6. Streamlit renders the markdown. The clone folder is deleted afterward.

## Security

Cloned repositories are **untrusted**. The app never executes `.py`, `.js`, shell scripts, binaries, or build commands. Files are opened as UTF-8 text only.

## Context limits (large repositories)

Configured in `backend/config.py`:

- Maximum number of files (`MAX_FILES`, default 25)
- Maximum characters per file (`MAX_CHARS_PER_FILE`, default 4000)
- Maximum total characters (`MAX_TOTAL_CHARS`, default 40000)
- Maximum clone working-tree size (`MAX_CLONE_BYTES`, default 80 MB)

Priority order: `README.md` → `package.json` / `requirements.txt` / `pom.xml` → other manifests → main entry files → `src/` → other source files.
